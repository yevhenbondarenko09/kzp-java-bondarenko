# Склад автозапчастин — лабораторна робота № 3

[![CI](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml/badge.svg)](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml)

Бондаренко Євген Віталійович, КІ-304. Варіант 4, рівень 2.

У цій лабораторній я продовжив консольну програму обліку автозапчастин. Вона читає CSV й записує однаковий звіт у консоль і UTF-8-файл. Рахує коректні записи, загальний запас і його вартість, знаходить найдорожчу деталь. Для хибних рядків указує номер і причину помилки.

## Вимоги та збірка

Потрібен JDK 21 або новіший. Maven Wrapper завантажує Maven 3.9.11, тому встановлювати Maven окремо не потрібно. Перший запуск потребує доступу до Maven Central. `JAVA_HOME` має вказувати на каталог JDK з `bin/javac`. Переконайтеся, що команда `java --version` також показує версію 21 або новішу.

Windows PowerShell, із кореня репозиторію:

```powershell
java --version
javac --version
.\mvnw.cmd -B clean verify
java -jar target/autoparts-all.jar
```

macOS / Ubuntu:

```sh
chmod +x mvnw
./mvnw -B clean verify
java -jar target/autoparts-all.jar
```

`verify` виконує компіляцію, JUnit-тести, пакування й SpotBugs. Окрема команда `package` не запускає SpotBugs, прив'язаний до пізнішої фази `verify`.

Виконуваний файл має сталу назву `target/autoparts-all.jar`, задану через `finalName` у POM. Версію показує `--version`; її зміна не змінює команду запуску.

Maven-модуль має назву `autoparts` (`artifactId`), тому в логах збірки відображається `@ autoparts`.

Кожна лабораторна має окрему основну версію: ЛР1 — 1.x.x, ЛР2 — 2.x.x, ЛР3 — 3.x.x. Версію змінюю тільки в `pom.xml`, після чого перебудовую JAR. Назва файла при цьому залишається сталою.

## Що змінилося після ЛР2

Я виділив спільний стан у abstract SparePart та створив final-підтипи OriginalPart і ReplacementPart. Поля sku, name, stock, unitPrice, supplier і PartKind незмінні; перевірки тексту, нулів і скінченності ціни збережені в базовому типі. Парсер параметрів, контролер і файловий шар залишилися окремими від Main.

Я обрав абстрактний клас, бо оригінал і замінник є різновидами деталі зі спільним станом та інваріантами. Контролер лише використовує ці об'єкти, тому не успадковує SparePart.

OriginalPart.warrantyCost повертає 10% ціни одиниці, ReplacementPart — 5%. Це навчальний гарантійний резерв на одиницю, незалежний від запасу. Обробка викликає метод через SparePart без розгалуження за підтипами. PartKind містить ORIGINAL/REPLACEMENT і українські підписи.

Final equals/hashCode визначають логічний дублікат за підтипом і артикулом. Ціна, запас, назва й постачальник на рівність не впливають. List зберігає повтори для підсумків, а HashSet окремо рахує унікальні деталі.

Для автотесту я зберіг фіксований набір у src/test/resources/lab03/input.csv: записи ЛР2 та випадки з обома підтипами, дублікатами, нулями й хибними NaN/kind. Файл data/lab03.csv використовується для ручного запуску; його можна редагувати незалежно від тестового набору.

У тестовому наборі 14 рядків: 10 прийнятих записів, запас 60 деталей, 8 унікальних позицій, вартість запасу 17500 грн, сума гарантійних резервів 540 грн і 4 хибні рядки. Найдорожчою залишається перша деталь із ціною 2000 грн (SKU-006), навіть із нульовим запасом. Для зміненого data/lab03.csv підсумки можуть відрізнятися: поточні артикули дають 9 унікальних позицій. CLI показує записи, запас, вартість і помилки; унікальні позиції та гарантійна сума перевіряються через Analysis у тестах.

InventoryReport.analyze повертає Analysis із прийнятими записами, помилками та StockValue. Через нього доступні uniqueCount і warrantyCost; старий CLI-звіт зберігає свій формат. За переповнення гарантійної суми метод повідомляє помилку окремо від підсумку запасу.

## Формат входу

Файл `data/input.csv`: UTF-8, без заголовка та коментарів, один запис у рядку, роздільник `;`. Поля не можуть містити `;` або перенесення рядка; CSV-лапки не підтримуються.

Після редагування зберігайте CSV саме в UTF-8: Windows-1251 (ANSI) спричиняє помилку читання. У VS Code натисніть назву кодування внизу вікна → Save with Encoding → UTF-8. Якщо файл уже в Windows-1251, спочатку виберіть Reopen with Encoding → Windows 1251, щоб правильно прочитати текст, а потім збережіть у UTF-8.

```text
sku;name;stock;unitPrice;supplier[;kind]
```

Шосте поле kind необов’язкове: ORIGINAL або REPLACEMENT. Без нього створюється OriginalPart. Явно порожня чи невідома категорія відхиляється. Спочатку перевіряється формат усіх полів, потім їхня валідність.

Цей рядок показує порядок полів; додавати його до файла не потрібно. `sku`, `name`, `supplier` містять непорожній текст. `stock` містить невід'ємне ціле до 2147483647, `unitPrice` містить скінченне невід'ємне число з десятковою крапкою. Допускаються нульові запас і ціна, пробіли по краях полів і UTF-8 BOM на початку файла. Кожен коректний рядок рахується окремо, навіть якщо артикул повторюється. За однакової максимальної ціни вибирається перший запис, незалежно від його запасу.

Приклад із репозиторію містить три коректні записи та два хибні:

```text
SKU-001;Brake pads;10;250.00;GrandAuto
SKU-002;Brake discs;4;1200.00;Modern
SKU-003;Windshield washer fluid;20;75.00;UkraAuto
SKU-004;Washer reservoir;-2;150.00;AutoImp
SKU-005;Interior light bulb;abc;350.00;ZapAuto
```

## Запуск і результат

```sh
java -jar target/autoparts-all.jar --help
java -jar target/autoparts-all.jar --version
java -jar target/autoparts-all.jar --input data/input.csv --output out/report.txt
```

Без аргументів використовуються `data/input.csv` та `out/report.txt` відносно поточної робочої теки. Для шляхів із пробілами потрібні лапки; можна передавати абсолютні шляхи. Вихідні каталоги створюються автоматично, наявний вихідний звіт перезаписується. Вхідний файл вихідним звітом перезаписати не можна. `--help` і `--version` запускаються окремо від інших параметрів.

```text
Склад автозапчастин — звіт
Коректних записів: 3
Загальна кількість деталей: 34
Вартість запасу: 8800.00 грн
Найдорожча деталь: SKU-002 — Brake discs; ціна: 1200.00 грн
Помилок: 2
Рядок 4: stock не може бути від'ємним
Рядок 5: stock має бути цілим числом у діапазоні int
```

Сума запасу зберігається в `long`, ціна і вартість — у `double`, вивід округлюється до двох знаків через `Locale.ROOT`. Це навчальна модель; для фінансового обліку з точною десятковою арифметикою потрібен `BigDecimal` або цілі копійки. NaN, нескінченність і переповнення вартості відхиляються. Для порожнього входу чи файла лише з помилками звіт містить нульові підсумки та повідомлення про відсутність найдорожчої деталі.

Коди завершення: `0` — звіт створено (навіть якщо частина або всі рядки хибні), довідку чи версію виведено; `1` — помилка читання/запису; `2` — помилка параметрів або спроба перезаписати вхід. Діагностика запуску пишеться у stderr, причини відхилення рядків — у сам звіт.

Для перевірки розширеного CSV:

```sh
java -jar target/autoparts-all.jar --input data/lab03.csv --output out/lab03.txt
```

ЛР3 має версію 3.0.0 з POM. Локальний clean verify виконує 83 сценарії; результати команд наведені в розділі 10 REPORT.md.

## Структура й перевірки

- `src/main/java/ua/lpnu/kzp/Main.java` — точка входу, UTF-8-потоки й код завершення.
- `src/main/java/ua/lpnu/kzp/ArgumentParser.java` — перевірка CLI та вибір шляхів.
- `src/main/java/ua/lpnu/kzp/InventoryController.java` — довідка, версія, запуск обробки й діагностика.
- `src/main/java/ua/lpnu/kzp/ApplicationInfo.java` — читання метаданих Maven зі зібраного ресурсу.
- `src/main/resources/application.properties` — шаблон версії та імені JAR; Maven підставляє значення з POM.
- `src/main/java/ua/lpnu/kzp/SparePart.java` — незмінна сутність, валідація конструктора, фабрика `fromCsv` і форматоване подання.
- `src/main/java/ua/lpnu/kzp/OriginalPart.java`, `ReplacementPart.java`, `PartKind.java` — підтипи та категорії.
- `src/main/java/ua/lpnu/kzp/StockValue.java` — незмінний record запасу й вартості.
- `src/main/java/ua/lpnu/kzp/FileReport.java` — файлові операції UTF-8.
- `src/main/java/ua/lpnu/kzp/InventoryReport.java` — список прийнятих SparePart, показники та форматування.
- `src/test/java/ua/lpnu/kzp/` — JUnit 5: обчислення, хибні дані, порожній набір, локаль, український текст, CLI та файлові помилки.
- `.github/workflows/ci.yml` — `clean verify`, запуск JAR і артефакти на трьох ОС; віддалений стан перевіряється в Actions.
- `REPORT.md` — звіт ЛР3; `docs/lab01/REPORT.md` — архів звіту ЛР1.

Каталоги `target/` та `out/` не додаються до Git. HTML-документацію можна створити командою `javadoc` із JDK. Для експорту звіту в DOCX потрібний Python: `python scripts/export_report.py --input REPORT.md --output REPORT_LAB03.docx`.
