# Склад автозапчастин — лабораторна робота № 1

[![CI](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml/badge.svg)](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml)

Бондаренко Євген Віталійович, КІ-304. Варіант 4, рівень 2.

Консольна Java-програма читає CSV із записами про автозапчастини й записує однаковий звіт у консоль і UTF-8-файл. Рахує коректні записи, загальний запас і його вартість, знаходить найдорожчу деталь. Для хибних рядків указує номер і причину помилки.

## Вимоги та збірка

Потрібен JDK 21 або новіший. Maven Wrapper завантажує Maven 3.9.11, тому встановлювати Maven окремо не потрібно. Перший запуск потребує доступу до Maven Central. `JAVA_HOME` має вказувати на каталог JDK з `bin/javac`. Переконайтеся, що команда `java --version` також показує версію 21 або новішу.

Windows PowerShell, із кореня репозиторію:

```powershell
java --version
javac --version
.\mvnw.cmd -B clean verify
java -jar target/lab01-1.0.0-all.jar
```

macOS / Ubuntu:

```sh
chmod +x mvnw
./mvnw -B clean verify
java -jar target/lab01-1.0.0-all.jar
```

`verify` виконує компіляцію, JUnit-тести, пакування й SpotBugs. Окрема команда `package` не запускає SpotBugs, прив'язаний до пізнішої фази `verify`.

## Формат входу

Файл `data/input.csv`: UTF-8, без заголовка та коментарів, один запис у рядку, роздільник `;`. Поля не можуть містити `;` або перенесення рядка; CSV-лапки не підтримуються.

Після редагування зберігайте CSV саме в UTF-8: Windows-1251 (ANSI) спричиняє помилку читання. У VS Code натисніть назву кодування внизу вікна → Save with Encoding → UTF-8. Якщо файл уже в Windows-1251, спочатку виберіть Reopen with Encoding → Windows 1251, щоб правильно прочитати текст, а потім збережіть у UTF-8.

```text
sku;name;stock;unitPrice;supplier
```

Цей рядок показує порядок полів; додавати його до файла не потрібно. `sku`, `name`, `supplier` містять непорожній текст. `stock` містить невід'ємне ціле до 2147483647, `unitPrice` містить скінченне невід'ємне число з десятковою крапкою. Допускаються нульові запас і ціна, пробіли по краях полів і UTF-8 BOM на початку файла. Кожен коректний рядок рахується окремо, навіть якщо артикул повторюється. За однакової максимальної ціни вибирається перший запис, незалежно від його запасу.

Приклад із репозиторію містить три коректні записи та два хибні:

```text
SKU-001;Brake pads;10;250.00;GrandAuto
SKU-002;Brake discs;4;1200.00;Modern
SKU-003;Windshield washer fluid;20;75.00;UkraAuto
SKU-004;Washer reservoir;-2;150.00;AutoImp
SKU-005;Interior light bulb;abc;350.00;ZapAuto
```

## Запуск і результат

```sh
java -jar target/lab01-1.0.0-all.jar --help
java -jar target/lab01-1.0.0-all.jar --version
java -jar target/lab01-1.0.0-all.jar --input data/input.csv --output out/report.txt
```

Без аргументів використовуються `data/input.csv` та `out/report.txt` відносно поточної робочої теки. Для шляхів із пробілами потрібні лапки; можна передавати абсолютні шляхи. Вихідні каталоги створюються автоматично, наявний вихідний звіт перезаписується. Вхідний файл вихідним звітом перезаписати не можна. `--help` і `--version` запускаються окремо від інших параметрів.

```text
Склад автозапчастин — звіт
Коректних записів: 3
Загальна кількість деталей: 34
Вартість запасу: 8800.00 грн
Найдорожча деталь: SKU-002 — Brake discs; ціна: 1200.00 грн
Помилок: 2
Рядок 4: stock не може бути від'ємним
Рядок 5: stock має бути цілим числом у діапазоні int
```

Сума запасу зберігається в `long`, ціна і вартість — у `double`, вивід округлюється до двох знаків через `Locale.ROOT`. Це навчальна модель; для фінансового обліку з точною десятковою арифметикою потрібен `BigDecimal` або цілі копійки. NaN, нескінченність і переповнення вартості відхиляються. Для порожнього входу чи файла лише з помилками звіт містить нульові підсумки та повідомлення про відсутність найдорожчої деталі.

Коди завершення: `0` — звіт створено (навіть якщо частина або всі рядки хибні), довідку чи версію виведено; `1` — помилка читання/запису; `2` — помилка параметрів або спроба перезаписати вхід. Діагностика запуску пишеться у stderr, причини відхилення рядків — у сам звіт.

## Структура й перевірки

- `src/main/java/ua/lpnu/kzp/Main.java` — параметри, виконання та коди завершення.
- `src/main/java/ua/lpnu/kzp/FileReport.java` — файлові операції UTF-8.
- `src/main/java/ua/lpnu/kzp/InventoryReport.java` — перевірка CSV, показники та форматування.
- `src/test/java/ua/lpnu/kzp/` — JUnit 5: обчислення, хибні дані, порожній набір, локаль, український текст, CLI та файлові помилки.
- `.github/workflows/ci.yml` — `clean verify`, запуск JAR і артефакти на трьох ОС; віддалений стан перевіряється в Actions.
- `REPORT.md`, `REPORT.docx` — звіт; `LAB01_CHECKLIST.md` — ручні кроки перед здачею.

Каталоги `target/` та `out/` не додаються до Git. HTML-документацію можна створити командою `javadoc` із JDK. Команда `python scripts/export_report.py` експортує звіт у DOCX; Python потрібний лише для експорту. Перед здачею перевірте верстку DOCX у Word або LibreOffice.
