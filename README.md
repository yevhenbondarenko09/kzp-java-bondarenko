# Склад автозапчастин — лабораторна робота № 5

[![CI](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml/badge.svg)](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml)

Бондаренко Євген Віталійович, КІ-304. Варіант 4, рівень 2.

У ЛР5 я додав `Repository<T>`, анотацію `@CsvColumn`, CSV-експорт через рефлексію та зворотне читання. Програма формує попередній звіт складу, а з параметром `--export` записує прийняті деталі в окремий CSV із заголовком. Потокові запити ЛР4 збережені.

## Вимоги та збірка

Потрібен JDK 21 або новіший. Maven Wrapper завантажує Maven 3.9.11, тому встановлювати Maven окремо не потрібно. Перший запуск потребує доступу до Maven Central. `JAVA_HOME` має вказувати на каталог JDK з `bin/javac`. Переконайтеся, що команда `java --version` також показує версію 21 або новішу.

Windows PowerShell, із кореня репозиторію:

```powershell
java --version
javac --version
.\mvnw.cmd -B clean verify
java -jar target/autoparts-all.jar
```

macOS / Ubuntu:

```sh
chmod +x mvnw
./mvnw -B clean verify
java -jar target/autoparts-all.jar
```

`verify` виконує компіляцію, JUnit-тести, пакування й SpotBugs. Окрема команда `package` не запускає SpotBugs, прив'язаний до пізнішої фази `verify`.

Виконуваний файл має сталу назву `target/autoparts-all.jar`, задану через `finalName` у POM. Версію показує `--version`; її зміна не змінює команду запуску.

Maven-модуль має назву `autoparts` (`artifactId`), тому в логах збірки відображається `@ autoparts`.

Поточна версія ЛР5: `5.0.0`. Її джерело в `pom.xml`; після зміни версії потрібно перебудувати JAR.

## Що змінилося після ЛР4

`InventoryReport` накопичує прийняті деталі через `Repository<SparePart>`. Метод `all()` повертає незмінний знімок, а `find(Predicate<? super T>)` відбирає записи без зміни сховища. Звіту й експорту передається один результат розбору CSV.

Модель із ЛР3 збережена: абстрактний `SparePart`, підтипи `OriginalPart` і `ReplacementPart`, enum `PartKind`. Запити працюють зі спільним типом.

`OriginalPart.warrantyCost()` повертає 10% ціни одиниці, `ReplacementPart` повертає 5%. Це навчальний гарантійний резерв на одиницю, незалежний від запасу. Для підрахунку суми використано поліморфний виклик через `mapToDouble(SparePart::warrantyCost)`.

Методи `equals` і `hashCode` оголошені як `final` і визначають логічний дублікат за підтипом і артикулом. Ціна, запас, назва й постачальник на рівність не впливають. List зберігає повтори для підсумків, а `distinct().count()` окремо рахує унікальні деталі.

Усі 95 попередніх тестових сценаріїв збережені. `SparePartRecord` містить п’ять полів варіанта для експорту, а `SparePart` продовжує зберігати підтип і поліморфну поведінку.

## Формат входу звіту

Файл `data/input.csv`: UTF-8, без заголовка та коментарів, один запис у рядку, роздільник `;`. Поля не можуть містити `;` або перенесення рядка; CSV-лапки не підтримуються.

Після редагування зберігайте CSV саме в UTF-8: Windows-1251 (ANSI) спричиняє помилку читання. У VS Code натисніть назву кодування внизу вікна → Save with Encoding → UTF-8. Якщо файл уже в Windows-1251, спочатку виберіть Reopen with Encoding → Windows 1251, щоб правильно прочитати текст, а потім збережіть у UTF-8.

```text
sku;name;stock;unitPrice;supplier[;kind]
```

Шосте поле kind необов’язкове: ORIGINAL або REPLACEMENT. Без нього створюється OriginalPart. Явно порожня чи невідома категорія відхиляється. Спочатку перевіряється формат усіх полів, потім їхня валідність.

Цей рядок показує порядок полів; додавати його до файла не потрібно. `sku`, `name`, `supplier` містять непорожній текст. `stock` містить невід'ємне ціле до 2147483647, `unitPrice` містить скінченне невід'ємне число з десятковою крапкою. Допускаються нульові запас і ціна, пробіли по краях полів і UTF-8 BOM на початку файла. Кожен коректний рядок рахується окремо, навіть якщо артикул повторюється. За однакової максимальної ціни вибирається перший запис, незалежно від його запасу.

Приклад із репозиторію містить три коректні записи та два хибні:

```text
SKU-001;Brake pads;10;250.00;GrandAuto
SKU-002;Brake discs;4;1200.00;Modern
SKU-003;Windshield washer fluid;20;75.00;UkraAuto
SKU-004;Washer reservoir;-2;150.00;AutoImp
SKU-005;Interior light bulb;abc;350.00;ZapAuto
```

## Запуск і результат

```sh
java -jar target/autoparts-all.jar --help
java -jar target/autoparts-all.jar --version
java -jar target/autoparts-all.jar --input data/input.csv --output out/report.txt
java -jar target/autoparts-all.jar --input data/lab04.csv --output out/lab05-report.txt --export out/parts.csv
```

Без аргументів використовуються `data/input.csv` та `out/report.txt` відносно поточної робочої теки. `--export` необов’язковий. Для шляхів із пробілами потрібні лапки; можна передавати абсолютні шляхи. Вихідні каталоги створюються автоматично, наявні результати перезаписуються. Вхід, текстовий звіт і CSV-експорт мають бути різними файлами; перевіряються також посилання на той самий файл. `--help` і `--version` запускаються окремо від інших параметрів.

```text
Склад автозапчастин — звіт
Коректних записів: 3
Загальна кількість деталей: 34
Вартість запасу: 8800.00 грн
Найдорожча деталь: SKU-002 — Brake discs; ціна: 1200.00 грн
Помилок: 2
Рядок 4: stock не може бути від'ємним
Рядок 5: stock має бути цілим числом у діапазоні int
```

Сума запасу зберігається в `long`, ціна і вартість — у `double`, вивід округлюється до двох знаків через `Locale.ROOT`. Це навчальна модель; для фінансового обліку з точною десятковою арифметикою потрібен `BigDecimal` або цілі копійки. NaN, нескінченність і переповнення вартості відхиляються. Для порожнього входу чи файла лише з помилками звіт містить нульові підсумки та повідомлення про відсутність найдорожчої деталі.

Коди завершення: `0` — звіт створено (навіть якщо частина або всі рядки хибні), довідку чи версію виведено; `1` — помилка читання/запису; `2` — помилка параметрів або спроба перезаписати вхід. Діагностика запуску пишеться у stderr, причини відхилення рядків — у сам звіт.

Для перевірки розширеного CSV:

```sh
java -jar target/autoparts-all.jar --input data/lab03.csv --output out/lab03.txt
```

Локальний `clean verify` пройшов на Windows із JDK 21: 145 сценаріїв без помилок і пропусків, SpotBugs без зауважень. Перевірки описані в розділах 11–12 [REPORT.md](REPORT.md).

## Потокові запити ЛР4

Клас `InventoryQueries` приймає `List<SparePart>` з обома підтипами. Для кожного запиту створюється окремий потік; джерело не змінюється. Списки результатів незмінні. Запити доступні через Java API та JUnit-тести; CLI зберігає попередній формат звіту.

| Метод | Контракт |
| --- | --- |
| `lowStock(parts, 5)` | `filter`: запас строго менше 5; на межі 5 деталь виключається |
| `skus(parts)` | `map`: усі артикули у вхідному порядку, включно з повторами |
| `stockValueByManufacturer(parts)` | `groupingBy` + `summingDouble`: сума `stock * unitPrice` за виробником |
| `priceStatistics(parts)` | `summarizingDouble`: count, sum, min, max, average ціни одиниці |
| `topByPrice(parts, 5)` | `sorted` перед `limit`: ціна за спаданням, назва за зростанням |
| `findBySku(parts, "A")` | `Optional`: перший точний збіг SKU незалежно від підтипу |

У ЛР4 п’яте поле містить виробника. Я зберіг технічну назву `supplier` і формат CSV для сумісності з попередніми роботами. У карті групування ключ має тип `String`; `TreeMap` впорядковує назви виробників. Категорії деталей залишаються в `PartKind`.

`n < 0` і від’ємний поріг відхиляються. `n = 0` дає порожній список, завелике N — всі доступні записи. Порожня статистика має count/sum = 0; її min/max потрібно відображати як «немає даних» після перевірки count, а не як нескінченності. Переповнення суми цін, вартості запасу або групового підсумку відхиляється. `null` для списку або ключа пошуку не дозволений; елементи списку мають бути валідними `SparePart`.

Контрольний набір `src/test/resources/lab04/input.csv` містить 8 записів: запас 28, вартість 5600.00 грн, 7 унікальних деталей, гарантійна сума 85.00 грн. За виробниками: Bosch = 1100.00, Brembo = 3300.00, Denso = 1200.00. Ціни: count = 8, sum = 1200.00, min = 0.00, max = 300.00, average = 150.00. Top-5 за артикулами: C, B, F, A, A. Старий звіт за рівної ціни 300.00 показує B як перший вхідний максимум.

```powershell
.\mvnw.cmd -B test
.\mvnw.cmd -B clean verify
.\mvnw.cmd -B package
java -jar target/autoparts-all.jar --input data/lab04.csv --output out/lab04-report.txt
```

## CSV-експорт та імпорт ЛР5

`SparePartRecord` має поля `article`, `name`, `quantity`, `price`, `manufacturer`. Текст непорожній, кількість невід’ємна, ціна скінченна й невід’ємна. На відміну від рівності старої моделі за SKU і підтипом, рівність цього запису враховує всі п’ять полів.

Експортер сортує анотовані поля за Java-іменами, а назви колонок бере з `@CsvColumn`. Заголовок і контрольний приклад із `data/lab05.csv`:

```csv
артикул,виробник,назва,ціна,кількість
A,Bosch,Фільтр,100.0,4
B,Brembo,"Колодки, передні",300.25,5
C,Denso,"Свічка ""Іскра""",0.0,0
D,Osram,"Лампа
фари",50.5,2
E,Bosch,Ремінь,200.0,6
```

Це 5 об’єктів і 7 фізичних рядків разом із заголовком. Поля з комою, лапкою або перенесенням беруться в лапки; внутрішня лапка подвоюється. Запис використовує UTF-8 і LF. Парсер читає весь документ та приймає LF, CRLF і CR, зберігаючи перенесення всередині полів.

```java
List<SparePartRecord> original = SparePartRecord.read(Path.of("data", "lab05.csv"));
CsvExporter.write(Path.of("out", "parts.csv"), SparePartRecord.class, original);
List<SparePartRecord> restored = SparePartRecord.read(Path.of("out", "parts.csv"));
// original.equals(restored) повертає true; зберігаються всі поля й порядок.
```

`CsvExporter` працює з будь-яким плоским класом, що має анотовані поля, включно з приватними полями базового класу. Порожній список дає файл лише із заголовком; імпорт порожнього файла також повертає порожній список. Схема, доступ до полів і записи перевіряються до відкриття файла на перезапис.

`DataStorageException` зберігає причини помилок файла, числа та доступу. Пошкоджені лапки, хибна кількість полів і заголовок відхиляються. У CLI помилка експорту дає код 1 і повідомлення в stderr.

Формат ЛР5 із комами та заголовком читає `SparePartRecord.read`; старий `--input` очікує формат звіту з `;`. Експорт містить п’ять полів за умовою варіанта й не зберігає `kind`. Для відновлення підтипів зберігайте початковий файл.

## Структура й перевірки

- `src/main/java/ua/lpnu/kzp/Main.java` — точка входу, UTF-8-потоки й код завершення.
- `src/main/java/ua/lpnu/kzp/ArgumentParser.java` — перевірка CLI та вибір шляхів.
- `src/main/java/ua/lpnu/kzp/InventoryController.java` — довідка, версія, запуск обробки й діагностика.
- `src/main/java/ua/lpnu/kzp/ApplicationInfo.java` — читання метаданих Maven зі зібраного ресурсу.
- `src/main/resources/application.properties` — шаблон версії та імені JAR; Maven підставляє значення з POM.
- `src/main/java/ua/lpnu/kzp/SparePart.java` — незмінна сутність, валідація конструктора, фабрика `fromCsv` і форматоване подання.
- `src/main/java/ua/lpnu/kzp/OriginalPart.java`, `ReplacementPart.java`, `PartKind.java` — підтипи та категорії.
- `src/main/java/ua/lpnu/kzp/StockValue.java` — незмінний record запасу й вартості.
- `src/main/java/ua/lpnu/kzp/FileReport.java` — файлові операції UTF-8.
- `src/main/java/ua/lpnu/kzp/InventoryReport.java` — список прийнятих SparePart, показники та форматування.
- `src/main/java/ua/lpnu/kzp/InventoryQueries.java` — чисті запити Stream API.
- `src/main/java/ua/lpnu/kzp/Repository.java` — типобезпечне сховище з незмінними знімками.
- `src/main/java/ua/lpnu/kzp/SparePartRecord.java` — плоска модель варіанта та імпорт CSV.
- `src/main/java/ua/lpnu/kzp/CsvColumn.java`, `CsvExporter.java`, `CsvParser.java` — схема, рефлексивний експорт і документний парсер.
- `src/main/java/ua/lpnu/kzp/DataStorageException.java` — помилки збереження з ланцюгом причин.
- `src/test/java/ua/lpnu/kzp/` — JUnit 5: обчислення, хибні дані, порожній набір, локаль, український текст, CLI та файлові помилки.
- `.github/workflows/ci.yml` — збірка через `clean verify`, запуск JAR і публікація артефактів на Windows, macOS та Ubuntu.
- `REPORT.md` — звіт ЛР5; `docs/lab01/REPORT.md`, `docs/lab02/REPORT.md`, `docs/lab03/REPORT.md` і `docs/lab04/REPORT.md` — архіви попередніх звітів.

Каталоги `target/` та `out/` не додаються до Git. HTML-документацію можна створити командою `javadoc` із JDK.
