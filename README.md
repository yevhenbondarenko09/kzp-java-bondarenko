# Склад автозапчастин — лабораторна робота № 2

[![CI](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml/badge.svg)](https://github.com/yevhenbondarenko09/kzp-java-bondarenko/actions/workflows/ci.yml)

Бондаренко Євген Віталійович, КІ-304. Варіант 4, рівень 2.

У ЛР2 я додав до програми обліку автозапчастин клас `SparePart` і record `StockValue`. Програма читає CSV, рахує коректні записи, загальний запас і його вартість та знаходить найдорожчу деталь. Звіт виводиться в консоль і записується у файл UTF-8. Для хибних рядків він містить номер і причину помилки.

## Вимоги та збірка

Для збірки й запуску потрібен JDK 21 або новіший. Maven Wrapper завантажує Maven 3.9.11 під час першої збірки, тому потрібен доступ до Maven Central. `JAVA_HOME` має вказувати на каталог JDK, а команди `java --version` і `javac --version` — показувати версію 21 або новішу.

Windows PowerShell, із кореня репозиторію:

```powershell
java --version
javac --version
.\mvnw.cmd -B clean verify
java -jar target/autoparts-all.jar
```

macOS / Ubuntu:

```sh
chmod +x mvnw
./mvnw -B clean verify
java -jar target/autoparts-all.jar
```

`verify` компілює код, запускає JUnit-тести, пакує JAR і виконує SpotBugs. Команда `package` завершується до фази `verify`, тому SpotBugs не запускає.

Версія ЛР2 — `2.0.0`, її задано в `pom.xml` і можна переглянути через `--version`. Виконуваний файл має сталу назву `target/autoparts-all.jar`, налаштовану в POM через `finalName`. Після зміни версії потрібно перебудувати JAR; команда запуску залишається тією самою.

## Що змінилося після ЛР1

У ЛР1 `InventoryReport` розбирав CSV у масив полів і працював з індексами. У ЛР2 я замінив запис об'єктом `SparePart`, а підсумки запасу й вартості об'єднав у record `StockValue`. Список `List<SparePart>` містить лише прийняті записи. Формат CSV, формули показників і контрольний звіт я зберіг.

`SparePart` має п'ять полів: `sku:String`, `name:String`, `stock:int`, `unitPrice:double`, `supplier:String`. Усі поля `private final`, сеттерів немає. Методи `sku()`, `name()`, `stock()`, `unitPrice()` і `supplier()` повертають значення. `toString()` форматує ціну через `Locale.ROOT`.

`SparePart.fromCsv()` спочатку перевіряє кількість і заповненість полів та розбирає числа. Потім конструктор перевіряє допустимість значень: текст не може бути null або порожнім, запас і ціна мають бути невід'ємними, ціна має бути скінченною. Нуль дозволений. Ці перевірки діють і за прямого виклику конструктора. Record `StockValue` відхиляє від'ємні підсумки, NaN та нескінченність.

`InventoryReport` перевіряє майбутню сумарну вартість до додавання об'єкта в список. Хибний рядок не змінює підсумки; у звіт потрапляють його номер і причина помилки. Для `a;b;-1;abc;s` першою буде помилка формату ціни, а для `a;b;-1;2;s` після розбору чисел буде повідомлення про від'ємний запас. Я обрав порядок «спочатку формат, потім валідність». На рядках із кількома помилками він може змінити перше повідомлення порівняно з ЛР1.

## Формат входу

Файл `data/input.csv`: UTF-8, без заголовка та коментарів, один запис у рядку, роздільник `;`. Поля не можуть містити `;` або перенесення рядка; CSV-лапки не підтримуються.

Зберігайте CSV у UTF-8. Файл із кирилицею у Windows-1251 програма не прочитає. Якщо файл уже збережено в Windows-1251, у VS Code виберіть Reopen with Encoding → Windows 1251, потім Save with Encoding → UTF-8.

```text
sku;name;stock;unitPrice;supplier
```

Це схема запису; у файлі мають бути лише значення полів. `sku`, `name` і `supplier` — непорожній текст, `stock` — невід'ємне ціле до 2147483647, `unitPrice` — скінченне невід'ємне число з десятковою крапкою. Нульові запас і ціна дозволені. Програма прибирає пробіли по краях полів і приймає UTF-8 BOM на початку файла. Кожен коректний рядок рахується окремо, навіть якщо артикул повторюється. За однакової максимальної ціни вибирається перший запис, незалежно від його запасу.

Приклад із репозиторію містить три коректні записи та два хибні:

```text
SKU-001;Brake pads;10;250.00;GrandAuto
SKU-002;Brake discs;4;1200.00;Modern
SKU-003;Windshield washer fluid;20;75.00;UkraAuto
SKU-004;Washer reservoir;-2;150.00;AutoImp
SKU-005;Interior light bulb;abc;350.00;ZapAuto
```

## Запуск і результат

```sh
java -jar target/autoparts-all.jar --help
java -jar target/autoparts-all.jar --version
java -jar target/autoparts-all.jar --input data/input.csv --output out/report.txt
```

Без аргументів програма читає `data/input.csv` і записує `out/report.txt`. Шляхи відлічуються від поточної робочої теки; можна вказати абсолютні. Шляхи з пробілами беруться в лапки. Програма створює вихідні каталоги й перезаписує наявний звіт. Вхід і вихід мають бути різними файлами. `--help` і `--version` запускаються окремо від інших параметрів.

```text
Склад автозапчастин — звіт
Коректних записів: 3
Загальна кількість деталей: 34
Вартість запасу: 8800.00 грн
Найдорожча деталь: SKU-002 — Brake discs; ціна: 1200.00 грн
Помилок: 2
Рядок 4: stock не може бути від'ємним
Рядок 5: stock має бути цілим числом у діапазоні int
```

Загальний запас зберігається в `long`, ціна і вартість — у `double`. Через `Locale.ROOT` суми виводяться з десятковою крапкою та двома знаками після неї. Для точних грошових розрахунків потрібен `BigDecimal` або цілі копійки. Програма відхиляє NaN, нескінченність і переповнення вартості. Порожній файл або файл лише з хибними рядками дає нульові підсумки й повідомлення про відсутність найдорожчої деталі.

Коди завершення: `0` — звіт створено (навіть якщо частина або всі рядки хибні), довідку чи версію виведено; `1` — помилка читання/запису; `2` — помилка параметрів або спроба перезаписати вхід. Діагностика запуску пишеться у stderr, причини відхилення рядків — у сам звіт.

## Структура й перевірки

- `src/main/java/ua/lpnu/kzp/Main.java` — точка входу, UTF-8-потоки й код завершення.
- `src/main/java/ua/lpnu/kzp/ArgumentParser.java` — перевірка CLI та вибір шляхів.
- `src/main/java/ua/lpnu/kzp/InventoryController.java` — довідка, версія, запуск обробки й діагностика.
- `src/main/java/ua/lpnu/kzp/ApplicationInfo.java` — читання метаданих Maven зі зібраного ресурсу.
- `src/main/resources/application.properties` — шаблон версії та імені JAR; Maven підставляє значення з POM.
- `src/main/java/ua/lpnu/kzp/SparePart.java` — незмінна сутність, валідація конструктора, фабрика `fromCsv` і форматоване подання.
- `src/main/java/ua/lpnu/kzp/StockValue.java` — незмінний record запасу й вартості.
- `src/main/java/ua/lpnu/kzp/FileReport.java` — файлові операції UTF-8.
- `src/main/java/ua/lpnu/kzp/InventoryReport.java` — список прийнятих SparePart, показники та форматування.
- `src/test/java/ua/lpnu/kzp/` — JUnit 5: обчислення, хибні дані, порожній набір, локаль, український текст, CLI та файлові помилки.
- `.github/workflows/ci.yml` — збірка через `clean verify`, запуск JAR і публікація артефактів на Windows, macOS та Ubuntu.
- `REPORT.md` — звіт ЛР2; `docs/lab01/REPORT.md` — архів звіту ЛР1.

Каталоги `target/` та `out/` не додаються до Git. HTML-документацію можна створити командою `javadoc` із JDK.
