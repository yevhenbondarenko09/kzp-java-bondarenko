## 1. Тема, номер і варіант

Лабораторна робота № 1 присвячена розгортанню Java-проєкту й базовій обробці текстових даних. Варіант 4 — облік складу автозапчастин.

Локальне середовище перевірки: Windows 10, amd64, PowerShell; Eclipse Temurin JDK 21.0.12.1; Maven 3.9.11 через Maven Wrapper. Публікація результатів на інших ОС перевіряється окремо в GitHub Actions.

## 2. Мета роботи

Створити Java-програму, яку можна відтворювано зібрати через Maven Wrapper, перевірити тестами та статичним аналізатором і запустити як виконуваний JAR. Навчитися читати UTF-8-файли, перевіряти записи, обчислювати показники предметної області та формувати звіт без залежності від локалі операційної системи.

## 3. Постановка задачі

Один запис має формат `sku:String;name:String;stock:int;unitPrice:double;supplier:String`. У файлі записуються тільки значення, без типів і заголовка. Файл закодовано у UTF-8; роздільник полів — `;`, десятковий роздільник — крапка.

| Поле | Зміст і обмеження |
| --- | --- |
| sku | Непорожній артикул |
| name | Непорожня назва деталі |
| stock | Ціла невід'ємна кількість у діапазоні int |
| unitPrice | Скінченна невід'ємна ціна одиниці |
| supplier | Непорожня назва постачальника |

Програма обчислює:

1. Кількість коректних записів.
2. Загальний запас — суму `stock`.
3. Загальну вартість запасу — суму `stock × unitPrice`.
4. Найдорожчу деталь — артикул і назву запису з максимальною `unitPrice` та його ціну.

За однакової максимальної ціни вибирається перший коректний запис. Нульові ціна та запас дозволені. Повторені артикули рахуються як окремі записи, бо завдання не вимагає їх об'єднання. Пробіли навколо полів прибираються. CSV-лапки й роздільник усередині поля не підтримуються.

Для кожного хибного рядка програма записує у звіт його номер і причину помилки, потім обробляє наступний. Хибні записи не впливають на підсумки. Якщо коректних записів немає, програма виводить нульові підсумки й повідомляє, що найдорожчу деталь не знайдено.

## 4. Структура програми

```text
data/input.csv
src/main/java/ua/lpnu/kzp/Main.java
src/main/java/ua/lpnu/kzp/FileReport.java
src/main/java/ua/lpnu/kzp/InventoryReport.java
src/test/java/ua/lpnu/kzp/MainTest.java
src/test/java/ua/lpnu/kzp/InventoryReportTest.java
pom.xml
mvnw
mvnw.cmd
.mvn/wrapper/maven-wrapper.properties
.github/workflows/ci.yml
.github/copilot-instructions.md
.github/agents/
scripts/export_report.py
README.md
REPORT.md
REPORT.docx
LAB01_CHECKLIST.md
```

Усі Java-класи належать пакету `ua.lpnu.kzp`, і шляхи відповідають назві пакета.

`Main` перевіряє параметри, вибирає шляхи, викликає файлові операції й обчислення. `--help` виводить довідку, `--version` — `1.0.0`. Без аргументів вхід — `data/input.csv`, вихід — `out/report.txt`. Коди завершення: 0 — успішний звіт, довідка чи версія; 1 — файлова помилка; 2 — помилка параметрів або спроба перезапису входу. Наявність хибних рядків сама по собі не є помилкою запуску.

`FileReport` читає рядки через `Files.readAllLines` і записує текст через `Files.writeString` з явним `StandardCharsets.UTF_8`. Створює батьківський вихідний каталог і перевіряє, чи не вказано той самий вхідний та вихідний файл, у тому числі через посилання на наявний файл.

`InventoryReport` розбиває рядок через `split(";", -1)`, перевіряє поля, перетворює запас і ціну та оновлює підсумки тільки після всіх перевірок. Підтримує UTF-8 BOM на початку файла. Для запасу використано `long`, щоб сума кількох великих значень int не переповнювала int. NaN, нескінченні ціни та переповнення вартості відхиляються. Один сформований текст передається обом приймачам.

Потік даних: параметри → UTF-8 CSV → перевірка кожного рядка → підсумки та список помилок → форматований текст → UTF-8-файл і консоль. Консольні потоки також явно використовують UTF-8; перенесення рядків — `%n` / `System.lineSeparator()`; числове форматування — `Locale.ROOT`.

Ціна й вартість зберігаються в `double` відповідно до навчального формату. Для точного фінансового обліку потрібен `BigDecimal` або цілі копійки. Програма завантажує вхідний файл у пам'ять цілком, тому розрахована на невеликі навчальні набори даних.

## 5. Інфраструктура

Координати Maven — `ua.lpnu.kzp:lab01:1.0.0`; Java release — 21; кодування — UTF-8.

| Компонент | Версія | Функція |
| --- | --- | --- |
| Maven Wrapper | 3.3.4 | Запуск Maven 3.9.11 |
| JUnit Jupiter | 5.12.2 | Тести зі scope test |
| Maven Compiler Plugin | 3.13.0 | Компіляція для Java 21 |
| Maven Surefire Plugin | 3.5.2 | Запуск JUnit 5 |
| SpotBugs Maven Plugin | 4.9.7.0 | Goal check у фазі verify |
| Maven Shade Plugin | 3.6.0 | Виконуваний JAR із класифікатором all |

Maven створює `target/lab01-1.0.0-all.jar` з `Main-Class: ua.lpnu.kzp.Main` у маніфесті. Залежностей часу виконання немає; JUnit потрібний лише тестам і не включається до JAR.

Команда `clean verify` виконує компіляцію, тести, пакування та SpotBugs. У Maven `package` передує `verify`; окрема команда `package` не запускає налаштований тут аналізатор.

Наявний workflow використовує JDK 21, кеш Maven, `clean verify`, запуск JAR з `--version`, звичайний запуск на прикладі даних та upload-artifact у матриці Ubuntu/Windows/macOS. Файл workflow перевірено локально; результати віддалених job ще потрібно підтвердити. Налаштування CI збережені як додаткова можливість понад обраний рівень 2.

`.gitignore` виключає `target/`, `out/`, IDE та локальний development shell; `.gitattributes` і `.editorconfig` задають правила текстових файлів.

## 7. Приклади роботи

Приклад `data/input.csv`:

```text
SKU-001;Brake pads;10;250.00;GrandAuto
SKU-002;Brake discs;4;1200.00;Modern
SKU-003;Windshield washer fluid;20;75.00;UkraAuto
SKU-004;Washer reservoir;-2;150.00;AutoImp
SKU-005;Interior light bulb;abc;350.00;ZapAuto
```

Збірка та звичайний запуск у Windows:

```powershell
.\mvnw.cmd -B clean verify
java -jar target/lab01-1.0.0-all.jar
```

У macOS/Ubuntu команда збірки — `./mvnw -B clean verify`. Потрібний JDK 21; за потреби встановлений JDK вибирають через `JAVA_HOME` та PATH поточного термінала.

Отриманий звіт:

```text
Склад автозапчастин — звіт
Коректних записів: 3
Загальна кількість деталей: 34
Вартість запасу: 8800.00 грн
Найдорожча деталь: SKU-002 — Brake discs; ціна: 1200.00 грн
Помилок: 2
Рядок 4: stock не може бути від'ємним
Рядок 5: stock має бути цілим числом у діапазоні int
```

Файл `out/report.txt` містить той самий текст. Контрольний розрахунок: `10 + 4 + 20 = 34`; `10 × 250 + 4 × 1200 + 20 × 75 = 8800`. Найбільша ціна — 1200.00. Хибні записи не змінюють жодного підсумку.

Інші режими:

```sh
java -jar target/lab01-1.0.0-all.jar --help
java -jar target/lab01-1.0.0-all.jar --version
java -jar target/lab01-1.0.0-all.jar --input data/input.csv --output "out/мій звіт.txt"
```

`--version` повертає `1.0.0`. Для відсутнього файла програма виводить у stderr «Помилка роботи з файлами» з системною причиною та повертає 1. Для `--input` без значення — повідомлення про потрібний шлях, підказку `--help` та код 2. Конкретний системний текст файлової помилки залежить від ОС.

## 8. Тестування

Виконано `.\mvnw.cmd -B clean verify` з JDK 21.0.12.1. Результат: `BUILD SUCCESS`.

| Набір перевірок | Кількість | Результат |
| --- | --- | --- |
| InventoryReportTest | 25 | 0 failures, 0 errors, 0 skipped |
| MainTest | 9 | 0 failures, 0 errors, 0 skipped |
| Разом JUnit 5 | 34 | Усі пройшли |
| SpotBugs | Аналіз основного коду | BugInstance size 0; Error size 0 |

Перевірено точний текст контрольного звіту, продовження після хибних рядків, порожній вхід, файл лише з помилками, відсутні поля, зайві поля, неправильні числа, від'ємні значення, переповнення int, NaN/Infinity і переповнення вартості. Окремо перевірено нульові значення, суму запасу понад int, BOM, пробіли, однакові максимальні ціни й незалежність від німецької локалі.

CLI-тести перевіряють довідку, версію, невідомі та повторені параметри, відсутні значення, некоректний шлях, відсутній файл, збереження входу при спробі його перезапису, неправильне UTF-8, вихідний шлях-каталог, автоматичне створення каталогів, українські символи та шляхи з пробілами. Консольний і файловий тексти порівнюються на рівність.

Додатково перевірено зібраний JAR як окремий процес: звичайний запуск, довідку, версію, абсолютні шляхи з пробілами з іншої робочої теки, порожній вхід, коди 1/2 для помилок, захист вхідного файла та запуск із німецькою локаллю JVM. UTF-8-байти stdout порівняно з файлом звіту — вони однакові. На прикладі отримано 3 коректні записи, запас 34, вартість 8800.00 і два повідомлення про помилки. Віддалені результати трьох ОС потрібно підтвердити окремо; локальні Windows-перевірки їх не замінюють.

Звіти Surefire після збірки містяться у `target/surefire-reports/`. Вони відтворюються командою `clean verify` й не додаються до Git.

## 11. Відповіді на контрольні питання

1. **Призначення pom.xml.** Це опис Maven-проєкту: його координат, залежностей, версії Java та плагінів збірки. Він задає, як відтворити збірку на іншому комп'ютері.
2. **Відмінність test, verify і package.** `test` запускає модульні тести, `package` проходить попередні фази й пакує JAR, а пізніша `verify` також виконує додаткові перевірки. У цьому проєкті саме verify запускає SpotBugs.
3. **Навіщо Wrapper.** Він запускає зафіксовану версію Maven без глобальної інсталяції Maven. JDK усе одно потрібно встановити.
4. **Роль main.** JVM починає виконання консольної програми з цього методу. `args` містить передані параметри командного рядка.
5. **Примітивний тип і String.** Примітивна змінна містить просте значення, наприклад число int; String є посилальним типом для незмінного тексту.
6. **Середнє в double.** Ділення цілих відкидає дробову частину. Потрібно перетворити один операнд на double до ділення та перевірити, що кількість не дорівнює нулю.
7. **Integer.parseInt для abc.** Виникне NumberFormatException, бо рядок не є записом цілого числа. У програмі помилка перетворюється на пояснення хибного поля stock.
8. **Чому не можна мовчки пропускати рядок.** Користувач не побачить, що частина даних не врахована. Тому звіт містить номер рядка та конкретну причину.
9. **split з другим аргументом -1.** Зберігає порожні поля в кінці рядка. Завдяки цьому порожній supplier можна відрізнити від коректного запису.
10. **Перевага Path.of.** Будує шлях із компонентів без ручного вибору роздільника ОС. Немає потреби складати шлях конкатенацією з Windows-зворотними скісними рисками.
11. **Явний UTF-8.** Прибирає залежність від системного кодування і забезпечує однакове читання та запис українських символів.
12. **Відмінність %n від \n.** %n у форматованому виводі підставляє системний роздільник рядків, а \n є конкретним символом LF.
13. **Перевірки варіанта 4.** Перевіряються п'ять полів, непорожні артикул, назва й постачальник, цілий невід'ємний запас, скінченна невід'ємна ціна та можливість обчислити вартість без переповнення.
14. **Тести середнього.** Значення 3 і 4 мають дати 3.5, що виявляє цілочислове ділення. Також потрібні один запис і порожній набір. У варіанті 4 середнє не обчислюється; тут перевірено суму запасу, добутки та максимум.
15. **Призначення аналізатора.** Шукає типові потенційні дефекти без виконання користувацьких сценаріїв. SpotBugs аналізує байт-код і доповнює, а не замінює тести.
16. **Роль GitHub Actions.** Автоматично виконує workflow для змін репозиторію. У цьому проєкті він має зібрати й перевірити один коміт на трьох ОС та опублікувати JAR.
17. **Issue на дефект.** Потрібні умови, кроки відтворення, очікуваний і фактичний результати. Корисно додати вхідні дані, команду та оточення; виправлення пов'язують через Closes #N.
18. **Розкриття ШІ.** Указують інструмент, ролі, запити, внесок людини й асистента, перевірки результату, прийняті рішення та особисту відповідальність автора.
19. **DevOps і Валідатор.** DevOps працює зі збіркою, залежностями, аналізатором, пакуванням і CI. Валідатор перевіряє поведінку та крайові випадки й формулює дефекти.
20. **Фрагмент для пояснення.** `line.split(";", -1)` зберігає порожні кінцеві поля, щоб програма могла виявити, наприклад, порожній supplier. Перевірка `Double.isFinite` перед оновленням підсумків відхиляє нескінченні значення й NaN.

## 12. Висновки

Для запуску на іншому комп'ютері потрібні JDK 21 і файл CSV у UTF-8. Перевірка на Windows виявила обидві залежності: Java 8 не запускає зібраний JAR, а CSV у Windows-1251 не проходить читання в UTF-8.

Перед здачею залишилося завершити PR, перевірити CI після останнього push, переглянути DOCX і подати звіт у ВНС. У лабораторній № 2 масиви полів можна замінити класом автозапчастини, зберігши файловий шар, CLI та налаштування збірки.
